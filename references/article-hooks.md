# Article Hooks Reference（长文 / article / 教程帖开头）

用于生成 X 长文、article、教程帖、方法论分享的开头。
重点不是一句话炸裂，而是让读者确认：这篇文章解决我现在的具体问题。

---

## Beefnoode 痛点目录型

来源：2025-10-27 @beefnoode 公开 X 长帖，主题为预测市场信息流搭建。
已抽象为结构，不复制全文。

**适合：** 教程、工具流、信息流搭建、赛道学习、方法论长帖、资源清单、从 0 到 1 操作指南。

**结构：**

1. **标题提问**：`【如何 {达成一个具体系统/能力}？】`
2. **痛点反问 1**：`你是不是也被 {低质内容/噪音/碎片信息} 淹没，想看 {高价值内容} 而不得？`
3. **痛点反问 2**：`你是不是也曾经抱着 {学习/赚钱/研究} 的心态打开 {平台}，结果陷进 {低效行为}？`
4. **条件承诺**：`如果有，那请认真看完这篇分享，至少能帮你 {具体收益}。`
5. **三问题目录**：`本文主要解决三个核心问题：第一，如何 {找源头}；第二，如何 {筛选/分类/处理}；第三，如何借助 {工具/流程} 搭建 {系统}。`
6. **正文推进**：每节用 `一、如何...` / `二、如何...` / `三、如何...`，降低长文阅读成本。
7. **末尾资产**：给名单、工具、模板、下一篇预告或评论区答疑。

**骨架：**

- `【如何 {打造/搭建/建立} 一个高质量 {系统}？】`
- `你的 {信息源/工作流/素材库} 是不是也被 {噪音} 刷屏，想看 {优质内容} 而不得？`
- `你是不是也曾经抱着 {目标} 打开 {平台/工具}，结果流连于 {碎片化/低价值动作}？`
- `本文主要帮你解决三个核心问题：如何 {找到}、如何 {处理}、如何 {搭建}`。
- `信息源/素材/账号不在于多，而在于精：{标准1} + {标准2} 才是关键。`

**生成提示：**

- 开头前 4 行一定要具体到场景，避免泛泛写“信息焦虑”。
- 三个问题必须能撑起文章目录，不能只是三个同义问题。
- 如果要做资源推荐，先讲筛选方法，再给名单；否则像纯搬运。
- 结尾用下一篇预告时，要绑定一个未展开的进阶点，例如自动化整理、AI 汇总、知识库联动。

**可套用示例：**

```markdown
【如何打造一个高质量 AI 选题信息流？】

你的时间线是不是也被各种模型新闻、搬运水文刷屏，想看真正能转化成选题的内容而不得？

你是不是也曾经抱着学习 AI 商业案例的心态打开 X，结果半小时后只收藏了一堆用不上的碎片？

如果有，这篇分享主要解决三个问题：
第一，如何找到真正高质量的信息源？
第二，如何把信息源按赛道和用途分类？
第三，如何借助工具搭建一个每天自动更新的选题流？
```

## 与短推钩子的区别

- 短推：前 0.5 秒制造冲突、数字或缺口。
- 长文：先确认痛点，再给目录，让读者相信后面有系统解法。
- 短推可以只靠一句判断；长文必须立刻交代“我会解决哪几个问题”。
